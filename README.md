# Mumbai healthcare: cardiovascular risk models and ward-level facility provision

An academic data-science project with two complementary modules, a web app and a five-page Power BI report:

1. **Cardiovascular risk prediction.** Three classifiers (Logistic Regression, Random Forest and an ANN) are trained
   on the Indian *Cardiovascular_Disease_Dataset* (Doppala & Bhattacharyya, 2021; 1,000 patients from one hospital).
   An interactive predictor compares all three. Predictions are **experimental and not clinically validated**.
2. **Mumbai healthcare infrastructure.** Listed public dispensaries, UPHCs, hospitals and maternity homes are compared
   with population across Greater Mumbai's 24 BMC wards. The module covers maps, ward indicators, the 288-row
   hospitals list and an exploratory K-Means grouping of wards.

The clinical data has no location field, so the two modules are never joined. No ward-level heart-disease rate is
inferred.

## Run it on Windows

You need Python 3.11+ (built and tested with 3.13). The easiest way is to double-click **`start_windows.bat`**, or run **`.\start_windows.ps1`** in PowerShell (`cmd /c .\start_windows.bat` in Command Prompt). It
creates `.venv`, installs the requirements, runs the pipeline if the models are missing, and starts the server.
To do the same by hand in Command Prompt, from the project folder:

```bat
py -3 -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python run_pipeline.py
.venv\Scripts\python -m pytest -q
.venv\Scripts\uvicorn backend.main:app --port 8050
```

* `run_pipeline.py` rebuilds all data, figures and models in about 2 minutes.
* `pytest` runs 68 tests.

Then open:
* <http://localhost:8050/>: the landing page.
* <http://localhost:8050/dashboard/>: the dashboard.
* <http://localhost:8050/api/docs>: the FastAPI Swagger docs.

On macOS or Linux, use `.venv/bin/` instead of `.venv\Scripts\`. The PDF report step
(`python -m src.build_report`) needs Google Chrome.

### Web app pages
All charts and the map are in the Power BI report. The web app keeps the numbers, the predictor and the embedded report.

| Tab | What it shows |
|---|---|
| Overview | Test-set cards for the three models, the facility KPIs, written observations, and a ward lookup that opens a ward's facilities and hospitals list |
| Heart risk predictor | A form for the 12 clinical inputs with validation and help text. "Fill from a real test-set patient" presets. All three model probabilities as gauges, agreement and uncertainty, and the disclaimer. "Submit as server form" posts to `/predict` and returns a server-rendered result |
| Power BI dashboard | The published Power BI report, embedded. It is also opened by the **Power BI Dashboard** button in the header. Set the link in `dashboard/powerbi-config.js`. Below it are CSV downloads |

### Power BI report (`powerbi/MumbaiHealth.pbip`)
The report has five pages: Home, Model performance, Patient data, Mumbai facilities (with the facility map) and Insights. It is
generated by `src/powerbi_project.py` from the CSVs in `powerbi/data/`. To open, refresh, publish and paste the embed link
into the web app, see **[powerbi/POWERBI_GUIDE.md](powerbi/POWERBI_GUIDE.md)**.

## Results (held-out test set, 200 patients)

| Model | Accuracy | Precision | Recall | F1 | ROC-AUC |
|---|---|---|---|---|---|
| Logistic Regression | 0.890 | 0.898 | 0.914 | 0.906 | 0.968 |
| Random Forest | 0.955 | 0.957 | 0.966 | 0.961 | 0.992 |
| ANN (MLP, 32 hidden units) | 0.935 | 0.948 | 0.940 | 0.944 | 0.986 |

The majority-class baseline scores 0.580 accuracy.

The high scores lean on the `slope` field, which almost separates the classes in this file. Without it, ROC-AUC is
0.948, 0.989 and 0.982. See [ML methodology](docs/ml_methodology.md), sections 5 and 6.

## Data sources
* **Clinical:** Doppala, B. P. & Bhattacharyya, D. (2021). *Cardiovascular_Disease_Dataset*. Mendeley Data V1,
  doi:10.17632/dzz48mvjht.1. Mendeley and Kaggle were blocked from the build environment, so the file in
  `data/raw/clinical/` is a public GitHub copy checked against the published schema. Replace it with the Mendeley
  download to confirm.
* **Facilities:** OpenCity / MCGM KMLs for dispensaries, UPHCs, public hospitals and maternity homes, plus the MCGM
  hospitals CSV (cp1252).
* **Wards:** the OpenCity Mumbai Wards Map (primary). It is cross-checked against `BMC_admin_wards.geojson` from
  github.com/sanjanakrishnan/mumbai_spatial_data: median IoU 0.986, lowest N at 0.840.
* **Population:** Census of India 2011, ward-wise. No 2023 ward table was in the project files.

### Original infrastructure-only instructions

The Mumbai pipeline still runs on its own. `run_pipeline.py` runs it first, followed by the boundary check and the
clinical stage. The original static dashboard notes follow.

After `run_pipeline.py`, serve the project root and open the dashboard:

```bash
.venv/bin/python -m http.server 8050 --bind 127.0.0.1
```

Then open <http://localhost:8050/>, the **landing page**. It explains the study, and its headline is live: pick any ward
and the sentence rewrites itself with that ward's sites, population and rate. From there, <http://localhost:8050/dashboard/>
is the **dashboard**. Its charts have moved to the Power BI report. The overview's ward lookup opens any ward's detail panel,
and `dashboard/#ward=R/S` opens a ward directly. It reads `powerbi/data/*.csv`, so re-running the pipeline and refreshing
the page updates it.

Raw inputs are already in `data/raw/` (downloaded from OpenCity on 2026-10-19; see the data quality report for
sources and SHA-256 hashes). The pipeline never modifies them.

## Key caveats

* Population is **Census 2011**, because no 2023 ward table was available. Facilities date from about 2025.
* Counts cover the MCGM facility layers only. 18 public hospitals in the hospitals CSV are missing from those layers.
* Most coordinates are rounded to about 1 km.
* K-Means is exploratory: 24 observations, and the clusters depend on the feature set. It is not one of the three models.
* The clinical models come from one Indian hospital's records. They are not Mumbai-specific and not clinically validated.
* The Power BI project was generated and validated on Linux (TMDL parser, PBIR schemas, tests) but not opened in Power BI
  Desktop, which runs only on Windows. Open it, refresh and publish it as described in `powerbi/POWERBI_GUIDE.md`.
